# SICOR KML datasets — how to use them for a better model

**Date:** 2026-07-07 · **Data:** `kml_sicor_2025/` (242,280 KMLs) + `kml_sicor_2026/` (66,296 KMLs),
generated by `extract_kml_sicor.py` from the SICOR rural-credit registry (2.45M operations →
348,847 with planting date in the 7 crops → 308,576 with gleba geometry). Same filename format as
`culturas/`. This plan says what each dataset is actually good for, verified against the current
training snapshots — several intuitive uses turn out wrong, and one contamination trap is live.

## 1. What these datasets are (measured, not assumed)

Parsed every filename (planting year) + a 150-file/crop centroid sample (region), and intersected
field IDs with the current snapshots:

**Identity: SICOR is the *same registry* as `culturas/`, not a second source.**
- 4,972 / 6,174 (81%) of current *training* fields appear in `kml_sicor_2025` by field_id.
- 982 / 1,373 (72%) of the *held-out test* fields appear in it too.
- **74 / 250 of the production benchmark KMLs appear in it.** ⚠️
- `kml_sicor_2025` ∩ `kml_sicor_2026` = 0; `kml_sicor_2026` ∩ (train ∪ test ∪ benchmark) = **0** —
  the 2026 safra is a genuinely clean, never-seen year.

**Planting years: safra ≈ planting calendar year here.**
- `kml_sicor_2025` is ~97% planting-year **2025** — the *same* year the model already trains on.
  **It does not contain the 2024 fields the production test failed on** (only ~500 annual-crop
  2024 plantings). The 2024 supply is still the `culturas/` pool (~276k, per STATUS_AND_ROADMAP
  Obstacle 1).
- `kml_sicor_2026` is ~99% planting-year **2026** — a brand-new crop-year. Summer crops
  (SOJA/MILHO planted Jan–Mar 2026) have completed seasons by now; winter cereals (TRIGO 11.7k,
  AVEIA 1.1k, planted Apr–Jun 2026) are **mid-season today**.
- Junk dates exist but are rare for annuals (ARROZ 2010, SOJA 2005…, plus 149 future-dated 2027).
  **CAFE is different**: 8.4k of safra-2025 CAFE has planting year 2024 and a long tail back to
  2000 — for a perennial that's the grove-establishment date, which is *legitimate* but means the
  feature window (planting +275d) can sit years in the past. Needs an explicit anchoring policy.

**Geography: same Sul-dominated distribution as the current training set** (ARROZ/AVEIA/TRIGO/
FEIJAO ~97–100% Sul; CAFE ~95% Sudeste). SICOR does **not** fix the regional bias. One bright
spot: MILHO-2026 is 31% Nordeste in the sample.

**Supply per crop (the numbers that matter):**

| Crop | sicor_2025 | sicor_2026 | Current train | Notes |
|---|--:|--:|--:|---|
| SOJA | 87,952 | 15,297 | 633 | incl. **838 safrinha-window (Jan–Mar 2025)** vs 32 in training |
| MILHO | 80,193 | 23,091 | 1,200 | incl. 8,625 safrinha-window 2025 |
| CAFE | 42,154 | 14,137 | 487 | planting-date semantics caveat above |
| TRIGO | 23,392 | 11,728 | 1,001 | all 2026 TRIGO is mid-season today |
| ARROZ | 3,530 | 365 | 637 | scarce everywhere — extract nearly all |
| FEIJAO | 3,271 | 559 | 1,016 | scarce — extract nearly all |
| AVEIA | 1,788 | 1,119 | 1,200 | scarce; 2026 batch is mid-season |

## 2. Ground rules before any extraction

2.1 **Global exclusion list (do this first — the trap is live).** 74 benchmark fields and 982
    held-out-test fields sit inside `kml_sicor_2025`. Build one canonical
    `excluded_field_ids.json` = {250 benchmark} ∪ {features_v8_test} ∪ {any future eval set} and
    make every sampler/extractor refuse those IDs. Otherwise the first big SICOR training batch
    silently absorbs the eval sets and every future metric is fiction.

2.2 **Dedupe by field_id across all KML roots** (`culturas/`, `dataset_split/`, both SICOR safras)
    — same registry, same IDs, real collision risk. Also de-accent crop prefixes
    (`FEIJÃO_`/`CAFÉ_` → ASCII) exactly like the pipeline does.

2.3 **Keep the two safras in separate folders** (answering the open question): year is the single
    most important stratification variable this project has — the production test just proved a
    14-point year effect. Merging folders destroys the cheapest label we have. Compose training
    mixes at extraction-manifest level (a JSON list of paths + metadata), never on disk.

2.4 **Move the KML libraries out of `best_models/datasets/`.** That folder is the byte-exact,
    checksummed snapshot of what the promoted models trained on (see MANIFEST.json). Raw KML
    supply belongs in `src/data/kml_sicor_{2025,2026}/`. Keeping 308k mutable files inside the
    frozen-artifact area invites exactly the provenance confusion the folder exists to prevent.

2.5 **Quality gates at sampling time:** reject junk planting years for annuals (keep 2024–2026),
    reject future-dated (2027) files, area sanity (drop <0.05 ha and >2,000 ha), and for CAFE
    decide the anchor policy: simplest defensible rule — keep CAFE with planting date ≥ 2023 (the
    +275d window then overlaps real Sentinel coverage and current grove state); revisit
    re-anchoring later.

## 3. What to use each dataset for

### `kml_sicor_2025` — same year, same region, 40× the volume. Three targeted uses, not bulk:

**A. Kill the safrinha-SOJA weakness with data (Roadmap Obstacle 3 — now trivially solvable).**
The current model leans on a 6× up-weight of 32 safrinha samples; the production test showed that
weight makes SOJA the default guess under shift (precision 0.67). SICOR-2025 has **838
safrinha-window SOJA** (+8.6k safrinha MILHO for the contrast class). Extract all 838 + ~2k
safrinha MILHO, retrain with the up-weight swept down toward 1–2×. Expected outcome: safrinha
recall from data instead of weight, SOJA over-prediction shrinks.

**B. Double the scarce classes.** ARROZ +3.5k and FEIJAO +2.8k essentially double those classes'
supply. Extract nearly all of both (post-gates).

**C. Within-year diversity top-up** for SOJA/MILHO/TRIGO/CAFE: stratified ~2k/crop (sample by
region × planting month, preferring non-Sul where available). Diminishing returns beyond that —
the marginal 80th-thousand Sul SOJA field teaches little.

### `kml_sicor_2026` — a clean unseen year. Its value is *evaluation first, training later*:

**D. The standing next-year benchmark (replaces improvised field tests).** Extract a stratified
~100/crop sample of *completed-season* 2026 fields (summer crops now; winter cereals after
~Nov 2026). Because 2026 ∩ everything = 0, this is a guaranteed-clean leave-one-year-out test —
the offline reproduction of exactly the condition the production test measured. Every model
promotion reports accuracy on it.

**E. Real mid-season truncation data.** TRIGO/AVEIA 2026 are mid-cycle *today*. Extract a few
hundred now (truncated grids) and re-extract the same fields after harvest (complete grids). That
pair validates the truncation-augmentation training (field-test plan Phase 4) against reality
instead of simulated masking — and measures how early in the season each crop is callable.

**F. After the safra closes (~Dec 2026):** fold 2026 into training → the first genuinely
multi-year model (2024 from culturas + 2025 + 2026), with leave-one-year-out as a standing
trainer report.

### What SICOR does *not* give — keep these on the roadmap unchanged:
- **2024** (the measured production failure) → still `culturas/` (Phase 2 of the field-test plan).
- **Regional diversity** (Cerrado/Matopiba/Norte) → still `culturas/`'s out-of-region tail.

## 4. Extraction batches & budget

Pipeline cost ≈ 4 Statistical-API calls/field (`phenology_feature_pipeline_v7.py`, rate-limited
8/s → ~7k fields/day realistic throughput).

| Batch | Fields | API calls | Purpose |
|---|--:|--:|---|
| B1: safrinha SOJA+MILHO (2025) | ~2.8k | ~11k | Use A — highest value/cost ratio |
| B2: ARROZ+FEIJAO all (2025) | ~6k | ~24k | Use B |
| B3: 2026 completed-season benchmark | ~0.5k | ~2k | Use D — do alongside B1 |
| B4: stratified top-up (2025) | ~8k | ~32k | Use C |
| B5: 2026 mid-season TRIGO/AVEIA | ~0.6k | ~2.4k | Use E (re-extract post-harvest, +2.4k) |
| B6: culturas 2024 pilot | ~5k | ~20k | The year fix (field-test plan Phase 2) |
| **Total near-term** | **~23k** | **~93k** | ~2 weeks of extraction at current rate |

Order: **B1 + B3 first** (one day, immediately actionable), then B6 (the production-gap fix),
then B2/B4/B5.

## 5. Experiment ladder (each step keeps the previous as baseline)

| Exp | Training mix | Question it answers | Gate |
|---|---|---|---|
| E0 (baseline) | features_v8 as-is | — | current: 84.3% on 250-KML bench |
| E1 | + B1 safrinha, up-weight sweep 6→1× | does data replace the weight? | safrinha recall ≥0.85 *and* bench SOJA precision ≥0.85 |
| E2 | + B6 culturas-2024 | does 2024 close the production gap? | 250-KML bench ≥0.95 covered acc |
| E3 | + B2/B4 volume | does volume still help after E2? | no regression, macro-F1 up |
| E4 | + truncation aug, validated on B5 | early-season serving | accuracy-vs-cutoff curve per crop |

Evaluation stack for every experiment: (i) features_v8_test (in-year sanity), (ii) the 250-KML
benchmark minus the 10 leaked fields (2024 condition), (iii) the B3 2026 benchmark (next-year
condition), (iv) safrinha + season diagnostics. Promotion requires (ii) and (iii), not just (i).
